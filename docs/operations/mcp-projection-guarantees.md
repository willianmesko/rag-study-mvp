# BE-12 MCP index and passage projection review

Reviewed source: `ce17d1d51623d4145764f01f0d8e762bd7d66224`, 2026-11-08 UTC.
This is a source/constraint/sink review of the remaining MCP read projections,
not a new decoder release or a claim that all backend rows are validated.

## Active embedding identity

[Migration 022](../../apps/api/db/migrations/022_workspace_embedding_indexes.sql)
constrains the selected fields of `workspace_embedding_versions`:

| Field | Existing guarantee | Consumer decision |
| --- | --- | --- |
| provider | Non-null TEXT restricted to ollama/openrouter/bedrock | Must match an explicitly priced configured identity |
| model | Non-null TEXT, one to 200 PostgreSQL characters | Must match the configured model exactly |
| dimensions | Non-null SMALLINT equal to 1024 | Must match the configured identity; retrieval also checks vector length |
| revision | Non-null UUID generated by PostgreSQL | Passed as a bound UUID parameter when rechecking the active index |
| active population | At most one committed row per tenant/state through a deferrable unique constraint | A missing active row refuses provider execution |

[PgMcpReadRepository.activeIndex](../../apps/api/src/modules/mcp/infrastructure/postgres/pg-mcp-read-repository.ts)
selects only those fields under a bound tenant filter and a bounded read-only
transaction. [McpHybridSearch](../../apps/api/src/modules/mcp/application/hybrid-search.ts)
requires a matching configured price with a finite nonnegative rate before
reserving budget or creating the embedding adapter. It does not interpret a
browser-supplied provider/model string as an approved choice.

The provider operation is limited to one redacted query embedding, with token/
cost reservation, a five-second deadline, propagated cancellation and no chat,
rewrite, reranker or fallback. The subsequent hybrid transaction rechecks the
active tenant/revision before using the vector. A changed version is refused;
there is no automatic model switch or index migration.

These physical scalar guarantees and the exact configured-identity check are
the intentional boundary for this projection. A new generic schema would mostly
repeat them. In particular, a JavaScript string-length check would not reproduce
PostgreSQL's character-length semantics for supplementary Unicode characters.
Do not loosen the database constraints or bypass the configured identity check
while adding a different provider or database driver.

## Passage and search projections

The query selects chunk UUIDs, nonnegative integer ordinals, nonempty TEXT
content, optional filtered security metadata and, for searches, document UUIDs,
SQL-clamped labels and a floating-point score. UUID/ordinal/content constraints
come from [migration 001](../../apps/api/db/migrations/001_initial.sql). Tenant
ownership is established by joining the document under its bound tenant filter;
the caller cannot override that scope through tool arguments.

Security metadata is intentionally `unknown`: it is untrusted JSON and cannot
be made trustworthy by a TypeScript row annotation. The SQL predicate requires
the low-risk label and caps passage character length; the selected security JSON
is size-limited. The shared stored-security reader treats missing/invalid labels
as high risk. The application then independently rejects non-low risk, nonempty
signals, excessive JavaScript length and freshly detected prompt injection.
It redacts PII before clipping a visible excerpt to 500 characters.

The separate SQL-character and JavaScript-length checks are intentional: an
oversized Unicode passage may be omitted by the application even if the SQL
character count admits it. Do not replace unknown metadata with a strict
OCR/language schema that makes legacy safe handling fail for the entire page.

Labels remain bounded and masked; internal paths and unsafe/private citation
URLs are omitted. Search emits similarity only when the value is finite and
within [-1, 1]. An undefined/invalid score is omitted, not converted into zero
or confidence. Dimension/finite checks on vector serialization are not a claim
that every possible provider vector has useful semantic quality or nonzero norm.

## Limits and transport checks

The [shared input schemas](../../packages/contracts/src/mcp.ts) limit source/
quality pages to ten, document/search passages to five and queries to 250
characters. `McpReadTools` parses those inputs before repository calls; direct
repository methods are internal capabilities, not public input boundaries. Some
repository methods additionally guard their limit before checkout. SQL binds
the selected limit and the hybrid candidate multiplier is fixed.

All current external read transports also check the shared output schema and
response-byte budget:

- [Workspace read endpoint](../../apps/api/src/modules/mcp/workspace-mcp.controller.ts).
- [Remote MCP transport](../../apps/api/src/modules/mcp/infrastructure/remote.ts).
- [stdio bridge](../../apps/api/src/interfaces/mcp/stdio.ts).

These checks sit alongside explicit tool allowlists, current membership/role
checks, consent or scoped credentials, budgets, deadlines and safe audit events.
Output validation does not establish authorization. New public/internal entry
points must either use this checked application path or define an equally
bounded contract before exposing raw repository methods.

## Existing execution evidence and limits

The [exact-source quality run](https://github.com/willianmesko/rag-study-mvp/actions/runs/42448152261)
passed the full harness and 97 actual PostgreSQL cases without skips. Relevant
existing fixtures include:

- [Read-tool policy](../../apps/api/src/modules/mcp/application/read-tools.test.ts):
  scope/argument caps, role checks, redaction, unsafe passage removal, private
  path hiding and explicit tool allowlists.
- [Hybrid search](../../apps/api/src/modules/mcp/application/hybrid-search.test.ts):
  reserve before exactly one embedding, no call for unavailable index/budget,
  retained accounting and provider cancellation.
- [Repository lifecycle](../../apps/api/src/modules/mcp/infrastructure/postgres/pg-mcp-read-repository.test.ts):
  read-only scope, bounded transactions, rollback/release and cancelled checkout.
- [Actual remote MCP](../../apps/api/src/modules/mcp/infrastructure/postgres/pg-mcp-remote.integration.test.ts):
  modern/legacy clients, tenant-scoped hybrid results, redacted excerpts,
  concurrent quotas, cancellation, membership revocation and safe audits.
- [Actual read transport](../../apps/api/src/modules/mcp/infrastructure/postgres/pg-mcp.integration.test.ts):
  selected-tenant reads, write rejection, scoped credentials and tool protocol.

No new test that simply repeats a type annotation, library, schema or hosted
change is needed for this documented decision. A new adapter/driver, removed
constraint or bypassing caller requires revisiting the review and its tests.
This is not a completed real ChatGPT OAuth consent test, a production
minimum-privilege credential rollout (BE-09), a semantic quality benchmark or
proof that heuristic prompt-injection screening catches every attack.

The remaining BE-12 action/OAuth/embedding and document/knowledge mappings retain
their separate sink/constraint reviews. Do not close the whole ticket based on
this bounded review.
