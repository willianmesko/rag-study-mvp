This release includes the earlier durable-conversation and guided-setup changes,
plus versioned workflow encryption support, safe operational telemetry, expanded
provider-usage accounting, budget notification delivery, upload/admission
idempotency and an invitation delivery journal. It does not automatically
activate a new hosted monitoring backend, live key rotation or a real webhook.

## Database changes

The following application migrations were applied to the existing Supabase
project and verified in `public.schema_migrations.version`:

- `20261107132459_observability_security_costs.sql`
- `20261107134302_resilient_integrations.sql`
- `20261107142238_idempotent_workspace_invitations.sql`

The new `budget_alert_outbox`, `integration_delivery_events` and
`workspace_invitation_requests` tables have RLS enabled and no SELECT grant for
`anon`, `authenticated` or `service_role`. Their intended access is the trusted
API connection, not the browser Data API. The security-advisor check added no
warning; previously recorded extension-schema/password-protection work remains
in the product backlog. No credentials or customer content were copied into
this evidence record.

  are BE-14 work; an audit report is not proof of exploitability.

## Production smoke check

Read-only checks confirmed:

- Frontend HTTP 200 and 18 served JavaScript assets. Published assets contain
  expanded-operation usage, unpriced-cost explanation and uncertain-invitation
  status handling.
- API `/health` HTTP 200, advertising OCR, durable workflows and conversations.
- A server-generated correlation ID replaces an arbitrary client-supplied ID.
- Unauthenticated usage-alert, conversation and invitation-delivery requests
  receive 401, without exposing private records.

This smoke check did not sign in as a real user, send an invitation, call a paid
provider, rotate a key or exercise a private customer document. Routine CI uses
synthetic identities and provider/email fixtures.
